# Application setup boundaries

Offline numerical verification needs NumPy/SciPy for the legacy results and standard-library Python for the mobile export. It does not need application execution, model weights, prompt files, a phone or cloud service.

## Source inspection

Use Python 3.10+ with the application's separately declared dependencies. From `application/`:

```bash
python -B main.py --help
```

```bash
python -B main.py --list-apps
```

`setup.py` reads the included application README; the placeholder project URL is replaced with the upstream URL. Source execution remains the declared entrypoint; package metadata checks are not an end-to-end installation or live-device check.

## Operator-supplied prompts

The research routing prompt and customized execution prompts are excluded. The following variables accept paths to the operator's own nonempty UTF-8 text files:

| Variable | Use |
| --- | --- |
| DUALROUTE_ROUTE_PROMPT_FILE | Python local route inference, llama-simple wrapper, validation helper and C++ worker |
| DUALROUTE_EXECUTION_PROMPT_ZH_FILE | Chinese execution agent |
| DUALROUTE_EXECUTION_PROMPT_EN_FILE | English execution agent |

These files are intentionally absent. There is no fallback prompt. The C++ worker reads the file before loading a model. The Python local route predictor resolves the prompt before loading a model. Supplying another prompt changes the generation configuration; this is not a reproduction of the paper's private inference configuration.

## Unbundled live requirements

Live Android execution additionally requires ADB, a compatible router weight/worker, phone setup, and an explicitly configured OpenAI-compatible GUI endpoint for Slow tasks. Model weights, ready-made workers, credentials and private endpoints are absent. The inherited llama.cpp build reference is `fbd441c37933550c1e3365dc84dd73232334c15d`; follow the supplied CMake source and upstream dependency license if building it separately. No third-party binaries or headers are redistributed here.

Historical default model names do not identify the deployed cp800 by themselves. The cp800 Q8 identity is retained by hash; no public weight download is asserted. Device/account/reset/cleanup and evidence requirements are outside this source snapshot. The formal Honor observations have already been collected and exported under `mobile_admission/`; they are not regenerated by these source commands.
